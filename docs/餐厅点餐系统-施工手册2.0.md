## 三、 当前正在解决的 Bug（交接第一优先级 ⚠️）

**问题定位**：在 `web/src/views/admin/TableManage.vue` 中，为了增加“按日期和餐段查看桌位状态”功能，引入了请求参数，导致系统崩溃。

**排查步骤与解决方案**：

1.  **前端参数嵌套错误**：
    *   **现象**：F12 中请求 URL 变成了 `.../table/page?params[tableNo]=&params[date]=...`。
    *   **解决**：检查 `TableManage.vue` 的 `getPageList` 方法，确保 `params` 是直接定义的平铺对象，不要写成 `{ params: { params: xxx } }`。
2.  **跨域拦截 (CORS) 报错**：
    *   **现象**：浏览器控制台报 `has been blocked by CORS policy`。
    *   **解决**：将后端的 `CorsConfig.java` 改为只保留一个 `CorsFilter` Bean，配置为 `addAllowedOriginPattern("*")` 并允许 `OPTIONS` 方法。
3.  **前端 TypeError 崩溃**：
    *   **现象**：跨域失败后，`http.js` 读取 `error.response.status` 报错。
    *   **解决**：修改 `web/src/utils/http.js`，在响应拦截器最前面加上 `if (!error.response) { ... }` 兜底判断。
4.  **后端 XML 解析报错**：
    *   **现象**：若 `DiningTableMapper.xml` 有 `<=`，启动会报错。
    *   **解决**：XML 中必须写成 `&lt;=`。

## 四、 历史重大“踩坑”与解决方案（答辩加分素材）

| 类别 | 踩坑现象 | 根因分析 | 解决方案 |
| :--- | :--- | :--- | :--- |
| **图片** | 手机扫码后图片裂开 | 数据库存 `http://localhost:1000/...`，手机以为是手机自己 | 前端封 `formatImg(url)`，自动替换为 `window.location.hostname` |
| **路由** | 点击某菜单跳 404 | 前后台路由 `name` 冲突 | 路由 `name` 必须全局唯一（如 `FrontReservation` / `AdminReservation`） |
| **路由** | 未登录扫码，登录后丢失桌号 | 守卫踢人时丢失了 URL Query | 守卫踢人时带上 `query: { redirect: to.fullPath }`，登录后回跳 |
| **MyBatis**| 启动报 `Mapped Statements already contains key` | Mapper 接口有 `@Select`，XML 里也有 | 同一方法只能写一处，联表复杂写 XML，删掉注解 |
| **后端** | 提交预订弹窗报 `400 Bad Request` | 实体类接收 `Date`，前端传 `YYYY-MM-DD` 字符串 | 实体类日期字段加 `@JsonFormat(pattern = "yyyy-MM-dd", timezone = "GMT+8")` |
| **前端** | 列表更新后数据错乱 | Vue 复用 DOM 节点导致渲染错位 | `<el-table>` 加上 `row-key="id"` |
| **业务** | 两个顾客同时抢一个桌位 | 并发冲突 | 前端 `selectAvailableTables` 动态过滤，后端 `checkConflict` 事务二次校验拦截 |
